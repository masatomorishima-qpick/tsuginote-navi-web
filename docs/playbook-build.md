# 作る係の手順書：検知から「止めた状態のキャンペーン」まで

作成 2026-10-31。給湯器（意図別の試験）・電気代・評価制度で実際に踏んだ手順を、そのまま型にしたもの。
目標は「検知から4時間以内、人の手は2回以下（変更依頼の取り込みと、配信の開始）」。
係の分担は docs/hypotheses.md の冒頭と同じ：探す係（毎朝の定期確認）→ 作る係（この手順書）→ 回す係・判定する係（毎朝の定期確認）。

## 0. 入力（探す係から受け取るもの）
- 候補の名前、起点の出来事、出来事の型（docs/trend-ads/watchlist.md の「2.」の6つのどれか）
- 条件1〜4の判定の根拠（docs/trend-ads/scan/<日付>.md の表の行）
- 紹介先の候補（案件名・ASP・報酬・成果地点・提携の状態）
これがそろっていなければ、作る係は動かず、探す係に戻す。

## 1. 紹介先を確かめる（最初にやる。ここで落ちる候補が一番多い）
1. A8（https://media-console.a8.net/）とレントラックスで案件の詳細を開き、次の4点を読む。
   - 成果条件と成果地点（申し込み完了か、供給開始か、面談完了か）
   - 否認条件に「リスティング」「検索広告」の語があるか。あれば使えない（例：モゲチェック 10/31）
   - 禁止語（社名・サービス名・商標が不可か。「バナーのみ使用可」か）
   - 確定率と EPC（規模の参考にだけ使う）
2. 提携の申請は**オーナーが行う**。作る係は「申請してほしい案件名」を1行で書いて渡す。即時提携を優先。
3. 承認前でもページと広告は作る。設定ファイルの `href` は空、`vetted: false` のまま置く（空のあいだは画面に出ない）。
4. 「承認済み」と書くのは、A8 の画面で「提携中」を自分の目で見たときだけ（10/30 にオクトパスエナジーを誤って承認済みと記録した反省）。
5. 入札の上限の初期値 ＝ 報酬 × 見込みの申込率 × 0.4。申込率の見込みは、申し込み型で 2〜5%、無料体験で 5〜10% から始める。

## 2. ページを作る（既存の型に設定ファイル1つ）
1. ページの型を決める：診断・計算・比較のどれか（watchlist.md の表の「ページの型」）。既存のページに入口を足せるなら、そちらを優先（例：給湯器の /jumyo・/hiyou の入口）。
2. 新規なら `lib/trend/<id>.ts` を書き、`lib/trend/registry.ts` に1行足し、`app/check/<id>/page.tsx` を置く。画面と計測は `components/trend/TrendCheck.tsx` が共通で受け持つので、触るのは設定ファイルだけ。
3. 設定ファイルに必ず入れるもの：
   - `version`（例 `v1-2026-11-01`。文言・設問・判定・紹介先を変えたら必ず上げる。版ごとに成績を比べるため）
   - `firstStepInline: true`（開始ボタンを置かず、最初の画面に1問目をそのまま出す。評価制度で開始ボタンが壁になった反省）
   - 事実の出典（数字を書いたら、設定ファイルの冒頭の注釈に出典の URL と確認日）
   - 紹介先は `vetted` と `href` がそろったものだけ出る。表示する順番は、結果の判定ごとに `partners` で指定
4. ページの決まり（LPの共通）：
   - ヘッダーは `LpHeader`（ロゴにリンクなし）、フッターは `LpFooter`（個人情報・利用規約・運営者だけ。他のページへ出る導線を置かない）
   - 中立性ポリシーへのリンクは、上部の PR 表示の横に1つだけ
   - 文字を減らし、図・アイコン・余白で見せる。見出しは文章にしない
   - 文言は利用者が普段使う言葉。校閲の水準で確認（「胡散臭さ」は申し込みを殺す）
   - 「必ず」「最安」は使わない。災害・人の死去は見出しに入れない
5. 手元で確かめる（`npx next dev`、幅390・高さ700の画面）：
   - 最初の画面に1問目と答えが収まる
   - 記録の順番が「表示 → 診断の開始 → 回答 → 結果 → 紹介先」になる（`/api/track` への送信を見る）
   - 紹介先が出る判定・出ない判定を1つずつ通す
   - 型の検査（`npx tsc --noEmit`）と書式の検査（`npx eslint`）が通る
6. 変更依頼を作る（`gh api repos/.../pulls -X POST`。`gh pr create` は使えない）。本文は「何を変えたか／なぜ／確かめたこと」。取り込みはオーナー。
7. 取り込まれたら、本番の画面で確かめる（見出し・1問目・紹介先の有無・他ページへのリンクが0）。本番の公開が失敗したら、オーナーに「キャッシュを使わずにやり直し」を頼む。

## 3. 広告を作る（止めた状態で）
1. キャンペーン：検索のみ、個別クリック単価（手動）、**日予算を必ず設定**（期間の合計予算だけにしない）、地域は紹介先の対応地域に合わせる、成果は「離脱クリック」（紹介先へのクリック）。作ったら**一時停止**にしてから中身を入れる。
2. 広告グループ：意図ごとに分ける（費用を知りたい／決めた・業者／比べる・寿命／症状 のように）。1グループ＝1つの意図＝1本の広告文＝1つの行き先。
3. キーワード：
   - 完全一致を中心に。新しい言葉だけ（毎年ある一般語は入れない）。作り方は watchlist.md の「2.」の〈固有名〉×〈出来事〉×〈行動〉
   - 1語ずつ、商品の語が入っているか・意図が合っているか・除外語と衝突しないかを目で確かめる（10/31 の全件監査で1,465語を見た）
   - 検索数の少ない言葉は「検索ボリュームが少ない」で単独では出ないが、意味が同じ検索として、出られる言葉から拾われる。それを前提に、各グループに「出られる言葉」を最低5語入れる
   - キーワードプランナーは最後に規模の参考として見るだけ。合否には使わない
4. 除外キーワード（キャンペーン全体）：共通（株価・求人・ニュース・速報・まとめ・pdf・英語 など）＋ 自分で直す・無料で済む行動の語（例：888・リセット・賃貸）＋ 案件の禁止語。
5. 広告文（レスポンシブ検索広告）：
   - 見出しは15本まで、1本は半角30文字（全角15文字）以内。説明文は90文字以内
   - 見出しの1本目は検索した言葉と同じ意図の言葉にし、位置1に固定（ピン）。行き先ページの H1 と同じ言葉にする
   - 事業者名・サービス名は、案件の禁止語に当たらないときだけ。当たるなら「大手3社」のように言い換える
   - 表示URLのパス（2つ）は意図が分かる日本語かローマ字に（例 denki/hojo）。重複させない
   - 「無料・登録不要」「〇問・〇秒」のように、押したあとに何が起きるかを書く
6. 補足の表示（短い補足文4つ、サイトリンク4つ）は**広告グループ単位**で、その意図に合うものを付ける。キャンペーン全体に1種類だけ付けると、意図の違うグループで文がずれる（10/31 の反省）。サイトリンクの行き先は LP の中の節（`#sumai` のような節の印）にして、LP の外へ出さない。
7. 計測：行き先の URL に `utm_source=google&utm_medium=cpc&utm_campaign=<名前>&utm_term={keyword}&utm_content={adgroupid}` を付ける。`gclid` は自動で付く。LP 側はこれを `lp_event_logs.metadata` に保存する（共通部品が受け持つ）。
8. できたら Google 広告の画面で「一時停止」のまま、オーナーに次を1枚で渡す：キャンペーン名と番号、日予算、地域、広告グループと言葉の数、広告文（全文）、上限の計算、止める条件（7日または1万円）。**配信の開始はオーナー**。

## 4. 仮説の表に1行足す（docs/hypotheses.md）
- 仮説（こうすれば、こうなるはず）、入れた日・版、測る数字、入れる前の数字、合格の基準、判定に必要な数、判定日。
- 合格の基準の既定値：送客率15%以上、1クリックの費用が上限の1.5倍以内、成果1件以上。
- 1つの画面で同時に変えるのは1つまで。重ねたときは「重ねた」と書く。

## 5. 時間の目安（watchlist.md の「3. 速攻の手順」と同じ）
| 時間 | すること | 人の手 |
|---|---|---|
| 0 | 検知（探す係） | — |
| +30分 | 紹介先の確認（1.）、提携の申請の依頼 | 申請はオーナー |
| +2時間 | ページ（2.）と変更依頼 | 取り込みはオーナー |
| +3時間 | 広告（3.）、止めた状態で | — |
| +3.5時間 | 仮説の表（4.）、オーナーへ1枚 | 配信の開始はオーナー |

## 6. やってはいけないこと（作る係にも適用）
お金を使う操作（配信の開始・予算や入札の変更）、提携の申請、フォームの送信、パスワードの入力、データの削除、変更依頼の取り込み、本番の公開のやり直し。すべてオーナーが行う。

## 7. つまずきやすい所（実際に起きたこと）
- 完全一致の多くは「検索ボリュームが少ない」になる。出られる言葉を各グループに置く（3.3）
- 広告文に社名・型番は入れない。キーワードには入れてよい
- 見出しの文字数（半角30）を超えると保存できない
- 補足の表示はキャンペーン全体に付けると意図がずれる。広告グループ単位で
- 本番の公開が「font の module が見つからない」で失敗することがある。キャッシュを使わないやり直しで直る（オーナー操作）
- `gh pr create` は使えない。`gh api` で作る
- 「承認済み」は管理画面で見てから書く
