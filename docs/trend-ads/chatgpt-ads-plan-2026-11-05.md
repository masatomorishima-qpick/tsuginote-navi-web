# ChatGPT 広告の設計（生成AI利活用計画書の早見表）2026-11-05

ChatGPT 広告に詳しい専門家の視点で設計。他事業の検証（2026年10月）の総括と、オーナーの方針（話題の指定を作り込む、答えの続きと誤認させない、パソコンだけで試す）を反映。

## 1. 仕様（2026年11月時点。出典は末尾）
- 構成：キャンペーン（目的・予算・期間・国・端末）→ 広告グループ（話題の指定と入札）→ 広告（見出し・説明文・画像・飛び先）
- 話題の指定（コンテキストヒント）：完全一致ではなく「描写した会話・話題に近いか」の手がかり。1語ではなく、何を・誰に・いつ役立つかを書いた説明的な句で。1グループに1つの相手・用途だけ。除外の指定はできない（否定文は入れない）
- 会話別の成績は見られない（成績はグループ単位・広告単位）→ 検討の段階ごとにグループを分ける
- 文字数：見出し3〜50字（推奨16〜24字）、説明文100字以内（推奨32〜48字）。画像は正方形のみ（最大1200×1200）
- 表示されるのは、ログインしている成人の無料版と Go の利用者だけ
- 端末：Android アプリ／Android ウェブ／パソコンのウェブ／iOS アプリ／iOS ウェブから選ぶ
- 日予算は「7日間の平均」。1日の上限は日予算の2倍、7日の上限は7倍。週は日曜〜土曜。止めても最大24時間は配信と請求が続く
- 広告利用規約8.5条：OpenAI の名前・ロゴを宣伝物に使うのは書面の許可なしでは禁止。ChatGPT の画面・語り口に似せた広告は修正・削除の対象
- 計測：OpenAI の計測タグ。申込みの標準の名前は lead_created。飛び先の URL に oppref が自動で付く（転送で落とさない）。成果の反映は24〜48時間遅れることがある
- 飛び先の巡回（OAI-AdsBot）を許可しておく
- 未確認：ヒント1本の文字数上限、日本語のヒントの扱い、パソコン向けアプリがパソコンのウェブに入るか、手動入札の最低額

## 2. 出す前に直したこと（11/5 対応済み）
- 早見表ページの説明文（検索結果や共有で出る文）に Clarity の計測コードが入っていた → 正しい説明文に直した
- 早見表の ChatGPT の個人の行に Go がなかった → 「無料・Go・Plus・Pro」に直した（Go は個人で契約するプランで、学習の扱いは他の個人プランと同じ）
- 残り：OAI-AdsBot がサーバーの防御設定で止められていないかを、管理画面の飛び先チェックで確認する

## 3. 広告グループ（3つ）
| グループ | 相手の状態 | 上限入札 |
|---|---|---|
| A 計画書を書いている最中 | 様式・チェックリストを埋めている。記入例がそのまま欲しい | 670円 |
| B 学習・履歴の根拠を調べている | 自分の契約で根拠が示せるか調べている | 600円 |
| C 通知への対応を調べている | 通知の中身や、何を確認されるかを把握する段階 | 500円 |

分ける理由：会話別の成績が見られないため、検討の段階をグループで分けて、どの段階が依頼につながるかを見る。依頼に近いほど入札を高くする。

## 4. 話題の指定（全文）
すべての文に2つの錨を入れる（①国交省・直轄・受注者・建設コンサルタント・測量・地質調査のどれか ②生成AI利活用計画書・発注者確認チェックリスト・業務計画書・特記仕様書のどれか）。一般の社内ルールや個人の学習設定だけの会話との近さを下げるため。

### A 計画書を書いている最中（10本）
1. 国土交通省直轄の建設コンサルタント業務を受注し、業務計画書と一緒に出す生成AI利活用計画書を書いている技術者
2. 生成AI利活用計画書の書き方や記入例を探している、国交省の測量業務・地質調査業務の受注者
3. 発注者確認チェックリストの6-3・6-4（学習に使われない措置とその根拠）に何を書くか迷っている受注者
4. 発注者確認チェックリストの7-3・7-4（利用履歴の保存方法とその根拠）の書き方を調べている受注者
5. 地方整備局の業務で監督職員に出す生成AI利活用計画書の記入欄の文案を、AIに手伝ってもらって作っている技術者
6. 報告書や成果品のとりまとめに生成AIを使う予定で、生成AI利活用計画書の提出を求められた建設コンサルタント
7. 生成AI利活用計画書に、使う生成AIのサービス名・契約プラン・学習させない設定の根拠を書き込もうとしている
8. 地方整備局が公開した生成AI利活用計画書のひな形と発注者確認チェックリストを埋めている受注者
9. 中小の建設コンサルタント会社で、国交省の業務ごとに生成AI利活用計画書を作る担当になった技術者
10. 業務計画書の提出が近いのに、生成AI利活用計画書の学習と履歴の欄だけ根拠が書けずに困っている受注者

### B 学習・履歴の根拠を調べている（8本）
1. 国交省の業務で使う生成AIが入力内容を学習に使わないことを、発注者に根拠つきで示したい受注者
2. ChatGPTの無料版やGoを国交省の業務に使っていて、学習させない設定で生成AI利活用計画書の根拠になるか調べている
3. 生成AIの利用履歴（会話の記録）の保存方法と保存期間を、生成AI利活用計画書にどう書くか調べている建設コンサルタント
4. 生成AIの利用規約やプライバシーポリシーのどの箇所を、発注者確認チェックリストの根拠として示せるか探している受注者
5. 国交省の発注者確認チェックリストに合わせるため、個人の無料プランから法人向けプランに切り替えるか比べている測量会社
6. 学習に使われない措置と利用履歴の保存の両方を満たせる生成AIの契約プランを、建設コンサルタント業務向けに比べている
7. 生成AIの会話履歴を会社側で保存して発注者に示せるか、管理者機能や履歴の書き出しを契約プラン別に調べている受注者
8. Copilot・Gemini・Claudeの契約プランで、国交省の生成AI利活用計画書の学習と履歴の根拠を示せるか確かめている技術者

（2と8の製品名は利用者に表示されない手がかり。審査で指摘されたら「生成AI」に置き換える）

### C 通知への対応を調べている（7本）
1. 2026年7月の国土交通省の通知で、直轄の測量・建設コンサルタント・地質調査業務に生成AI利活用計画書が必要になった内容を調べている
2. 国交省の業務で生成AIを使って報告書をまとめてよいのか、発注者に何を出して何を確認されるのかを知りたい受注者
3. 建設コンサルタント会社の生成AI推進担当として、国交省の生成AI利活用計画書に今の利用環境で対応できるか確かめている
4. 公共事業の受注者として生成AIを使うとき、発注者確認チェックリストでどの項目を根拠まで問われるのか把握したい
5. 社員が個人契約の生成AIを業務に使っている中小の測量・地質調査会社で、国交省業務に向けて契約と使い方を見直している
6. 生成AIを使った成果品のとりまとめについて、特記仕様書や業務計画書でどんな記載が求められるか調べている建設コンサルタント
7. 国交省の通知を受けて、生成AIを使う業務と使わない業務の線引きと計画書の出し方を社内で決めようとしている技術管理部門

## 5. 広告文と画像
決まり：製品名（ChatGPT・Copilot・Gemini・Claude）は入れず「主要4サービス」と書く。「公式」「国交省推奨」は使わない。見出しは名詞で終え、語りかけ・問いかけ・「続きはこちら」「回答」は使わない。「受注者向け」「外部ページ」「外部サイト」を入れる。自動で作られる下書きは使わない。

| グループ | 見出し | 説明文 |
|---|---|---|
| A | ①生成AI利活用計画書の記入例 ②計画書6-3・7-3の書き方と記入例 | ①建設コンサル・測量・地質の受注者向け。6-3〜7-4の記入例を外部ページで（無料） ②発注者確認チェックリスト6-3・6-4・7-3・7-4の書き方。お使いの契約に合わせた記入例を無料でお送りします |
| B | ①契約プラン別 学習・履歴の根拠表 ②生成AIの学習・履歴 ○△×早見表 | ①主要4サービスを契約プラン別に○△×で整理。公式資料の出典つきの外部ページ ②個人契約の無料プランでは根拠を示しにくい項目も。国交省業務の計画書向けに整理した早見表（外部サイト） |

## 7. 計測
- 飛び先：https://blueadventures.jp/ai-plan-hayamihyo/?utm_source=chatgpt&utm_medium=cpc&utm_campaign=ai-plan&utm_term=（a/b/c）&utm_content=（a1〜c2）&from=gpt
- OpenAI の計測タグ：早見表ページとお礼ページに基本のコードを置き、お礼ページでだけ lead_created を1回送る（フォーム送信の直前に閲覧中だけ残る印を置き、印があるときだけ送って消す。再読み込みでの二重計上を防ぐ）
- Clarity：お礼ページで送信の印を記録し、広告別に滞在・読み進み・フォーム到達・送信を見る
- フォームの「流入元（自動入力）」で、依頼ごとの経路を確認する
- プライバシーポリシーに「アクセス解析・広告の計測」（Google アナリティクス、Microsoft Clarity、Google 広告、OpenAI）を足す（オーナー確認のうえ保存）

## 8. 毎日見る数字と判断
目標：1週間で依頼2件（1件あたり8,750円以下）、最低1件。1クリック450円前後なら約35クリックで依頼率5.7%が必要。

毎日（日本時間9時すぎ）：グループ別・広告別の表示・クリック・クリック率・1クリック単価・費用・端末／Clarity の訪問・10秒以上の滞在・表まで読んだ割合・フォーム到達・送信／lead_created とフォームの回答数／管理画面のクリックと Clarity の訪問の比（8割未満なら計測漏れを疑う）

3日目（11/11 9時）
| 状態 | 打ち手 |
|---|---|
| 表示が累計300未満 | 全グループを670円に。足りなければ言い回しを変えたヒントを各5本足す（錨は外さない） |
| 表示500以上でクリック率0.7%未満のグループ | 広告文と画像を差し替え。0.5%未満で費用の半分以上ならそのグループを止める |
| クリック15以上で10秒以上の滞在が30%未満 | Clarity の録画で、最初の画面と広告が合っているかを見る |
| フォーム到達20%以上で送信0 | フォームを直す |

7日目（11/15 9時）
| 状態 | 判断 |
|---|---|
| 依頼2件以上 | もう1週。成績のよいグループに予算を寄せる |
| 依頼1件 | 直してもう1週 |
| 依頼0・クリック30以上・フォーム到達15%以上 | フォームを直してから1週 |
| 依頼0・クリック30以上・フォーム到達15%未満 | 広告を止めて早見表ページを直す |
| 依頼0・クリック20未満 | この媒体では会話の量が足りない。検索広告に予算を移すか判断 |
